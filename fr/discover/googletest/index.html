Tests unitaires et simulations C++ conformes aux standards de l'industrie

GoogleTest et GoogleMock fournissent des tests unitaires, des objets fictifs (mocks) et des suites de tests paramétrés pour le C++ moderne.

Ce que vous gagnez

  • Macros d'assertion complètes: Diagnostics clairs avec ASSERT_* (fatal, arrête le test) et EXPECT_* (non fatal, poursuit le test).
  • Suite de simulation avancée (GoogleMock): Isolez les dépendances avec MOCK_METHOD pour simuler facilement des interfaces et vérifier les appels.
  • Tests paramétrés par valeurs: Exécutez la même logique de test sur des dizaines de jeux de données grâce aux tests paramétrés.
  • Sécurité des threads multiplateforme: Exécution thread-safe sous Linux, macOS et Windows avec tests de mort (death tests) fiables.
  • Intégration CI/CD et rapports: Intégration transparente aux pipelines GitHub Actions et GitLab CI via les sorties XML et JSON JUnit.

Installation

Intégration via CMake FetchContent
include(FetchContent)
FetchContent_Declare(
  googletest
  URL https://github.com/google/googletest/archive/refs/tags/v1.15.2.tar.gz
)
FetchContent_MakeAvailable(googletest)

Compiler et exécuter via CTest

cmake --build build
ctest --test-dir build --output-on-failure

Architecture technique et principe de fonctionnement

GoogleTest repose sur une conception C++ modulaire optimisée pour les compilateurs modernes:

  • Gestion du cycle de vie des fixtures de test: Les méthodes SetUp et TearDown assurent une allocation et une libération déterministes des ressources.
  • Isolation des processus pour les death tests: Isole des processus enfants pour vérifier en toute sécurité les plantages et statuts d'erreur.
  • Modèles de tests paramétrés par type: Permet de valider des classes génériques C++ sur plusieurs types de données sans duplication.

Scénarios de test et intégration de GoogleMock

L'isolation des dépendances via des objets fictifs (mocks) en C++ moderne offre des avantages pratiques majeurs:

  • Abstraction des appels réseau et base de données: Simulez les réponses d'API et les latences sans connexions réelles grâce à MOCK_METHOD.
  • Vérification des comptages d'appels et arguments: Contrôlez le nombre d'invocations, les paramètres et l'ordre des appels avec EXPECT_CALL.
  • Tests de résilience face aux exceptions: Validez la gestion robuste des erreurs sur les chemins levant des exceptions avec EXPECT_THROW.

Foire aux questions

  • Quelle est la méthode moderne pour inclure GoogleTest? Dans les projets CMake modernes, FetchContent est l'approche recommandée, téléchargeant et compilant GoogleTest directement dans le projet sans gestionnaire externe.
  • Quelle est la différence entre EXPECT_* et ASSERT_*? Les macros EXPECT_* signalent une anomalie mais permettent au test de continuer. Les macros ASSERT_* arrêtent immédiatement la fonction de test en cours en cas d'échec.
  • GoogleMock est-il une bibliothèque distincte? GoogleMock était autrefois autonome mais est intégré au dépôt unifié GoogleTest depuis plusieurs années; ils s'installent conjointement.
  • GoogleTest est-il thread-safe? Oui. Sur les systèmes compatibles pthreads et sous Windows, GoogleTest gère en toute sécurité les assertions émises par des threads concurrents.
