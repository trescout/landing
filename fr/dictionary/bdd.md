# Qu'est-ce que BDD ?

> Behavior-Driven Development

Le processus de développement consistant à définir comment un logiciel doit se comporter dans des phrases simples que tout le monde peut comprendre.

## Définition
BDD permet à des personnes non techniques d'être impliquées dans le processus de développement logiciel. Il se concentre sur ce que l'utilisateur fera et sur la façon dont le système réagira, plutôt que sur les détails techniques du logiciel. Grâce à cette méthode, les développeurs et les business units parlent le même langage.

## Comment ça marche
Premièrement, le comportement attendu du système s'écrit « Si l'utilisateur fait X, le résultat Y devrait se produire ». Ces phrases sont ensuite codées et testées. Si le code répond à ce comportement, le logiciel fonctionne correctement.

## Où est-ce utilisé
Il est utilisé dans les projets logiciels, notamment dans le développement de fonctionnalités complexes et pour réduire la marge d’erreur.

## Souvent confondu avec
Peut être confondu avec TDD ; Alors que TDD se concentre sur la robustesse du code, BDD se concentre sur le comportement de la fonction aux yeux de l'utilisateur.

## Questions fréquentes
**Pourquoi le BDD est-il important ?**
Il élimine le fossé de communication entre l’équipe technique et l’équipe commerciale.

**BDD nécessite-t-il une langue spéciale ?**
Habituellement, une syntaxe simple est utilisée, comme Gherkin, qui est très proche de l'anglais et peut être lue par n'importe qui.
