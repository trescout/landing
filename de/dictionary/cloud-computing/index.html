Cloud Computing Architektur, Modelle und System-Engineering

Cloud Computing bezeichnet die bedarfsgerechte Bereitstellung von IT-Ressourcen wie Servern, Speicher, Datenbanken und Netzwerkinfrastruktur über das Internet nach dem Pay-as-you-go-Prinzip.

Definition, etymologischer Ursprung und konzeptionelle Grundlagen

Der Begriff Cloud Computing stammt aus Telekommunikationsdiagrammen der 1990er Jahre, in denen komplexe Netzwerkinfrastrukturen symbolisch als Wolke dargestellt wurden. Statt teure lokale Rechenzentren aufzubauen, greifen Unternehmen über APIs flexibel auf elastische Rechnerkapazitäten zu.

Servicemodelle und Bereitstellungsformen (IaaS, PaaS, SaaS, Serverless)

Cloud-Lösungen gliedern sich in vier grundlegende Ebenen:

  • IaaS (Infrastructure as a Service): Virtualisierte Rechenleistung, Festplattenspeicher und virtuelle Netzwerke (AWS EC2, Google Compute Engine).
  • PaaS (Platform as a Service): Verwaltete Entwicklungs- und Laufzeitumgebungen ohne manuelles Betriebssystem-Patching (Heroku, Render).
  • SaaS (Software as a Service): Vollständige Softwareanwendungen, die über den Webbrowser genutzt werden (Google Workspace, Salesforce).
  • Serverless / FaaS: Ereignisgesteuerte Code-Ausführung mit sekundengenauer Abrechnung ohne Server-Leerlaufkosten (AWS Lambda, Cloudflare Workers).

Systemarchitektur: Hypervisoren, Container und CAP-Theorem

Die technische Grundlage des Cloud Computing bilden moderne Virtualisierung und verteilte Systeme:

  • Hypervisoren und Container: Typ-1-Hypervisoren (KVM, ESXi) virtualisieren vollständige Betriebssysteme, während Container (Docker, containerd) den Host-Kernel teilen und minimale Startzeiten bieten.
  • CAP-Theorem und Konsens: Globale Cloud-Dienste müssen die Balance zwischen Konsistenz (Consistency), Verfügbarkeit (Availability) und Partitionstoleranz wahren, gestützt auf Algorithmen wie Raft oder Paxos.

Wirtschaftliche, ökologische und geopolitische Dimensionen

Der Wechsel in die Cloud wandelt Investitionsausgaben (CapEx) in flexible Betriebsausgaben (OpEx) um, erfordert jedoch FinOps-Praktiken gegen unerwartete Datenübertragungsgebühren. Datenschutzgesetze (DSGVO) verlangen zudem eine verifizierte regionale Datenhaltung mit robuster Verschlüsselung.

Häufige Verwechslungen

  • Cloud Computing vs. Klassisches Webhosting: Webhosting stellt starre Ressourcen auf einzelnen Servern bereit, während die Cloud dynamische Autoskalierung über weltweite Verfügbarkeitszonen bietet.
  • Private Cloud vs. Lokaler Serverraum: Ein Server im Keller ist keine Private Cloud ohne vollautomatisierte API-gestützte Ressourcenorchestrierung.
Cloud Computing gleicht der modernen Stromversorgung: Statt ein eigenes Dieselkraftwerk im Keller zu warten, nutzt man die Steckdose und bezahlt exakt die abgerufenen Kilowattstunden.

Häufig gestellte Fragen

Was sind die zentralen Vorteile von Cloud Computing?

Sofortige Skalierbarkeit, weltweite Ausfallsicherheit, Wegfall von Hardware-Wartung und schnelle Markteinführung digitaler Produkte.

Was unterscheidet Multi-Cloud von Hybrid Cloud?

Multi-Cloud kombiniert Dienste verschiedener öffentlicher Anbieter (z. B. AWS und Azure), während Hybrid Cloud private Rechenzentren mit öffentlichen Cloud-Instanzen verknüpft.

Wie lassen sich Cloud-Ausgaben nachhaltig optimieren?

Durch Etablierung von FinOps-Routinen, Autoscaling-Regeln, Nutzung von Spot-Instanzen und Reduzierung ungenutzter Speicherressourcen.
