# Was ist TDD?

*Glossar · Dev · Zuletzt aktualisiert: 11. Juli 2026*

> Test-Driven Development

Es handelt sich um eine Entwicklungsmethode, die darauf basiert, zunächst den Test des zu schreibenden Codes vorzubereiten und dann genügend Code zu schreiben, um diesen Test zu bestehen.

## Definition

TDD basiert auf der Philosophie „Erst testen, dann Code erstellen“. Zuerst schreiben Sie einen Test, der definiert, was der Code tun soll; Natürlich schlägt dieser Test fehl, da noch kein Code vorhanden ist. Dann schreiben Sie den einfachsten Code, der den Test besteht. Dieser Zyklus stellt sicher, dass die Software in jedem Schritt fehlerfrei ist.

***Analogie:** Es ist so, als würde ein Lehrer, der eine Prüfung vorbereitet, zunächst den Lösungsschlüssel erstellen und dann von den Schülern erwarten, dass sie ihn anhand dieses Schlüssels bestehen.*

## So funktioniert es

Dreistufiger Zyklus: 1. Test schreiben (Fehlgeschlagen), 2. Code schreiben (Test bestehen), 3. Code bereinigen (Refactor). Dieser Vorgang wiederholt sich ständig.

## Wo es eingesetzt wird

Es wird in modernen Softwareentwicklungsteams angewendet, insbesondere in Projekten, bei denen Sicherheit und Qualität im Vordergrund stehen.

## Häufig verwechselt mit

Es kann mit Unit Testing verwechselt werden; TDD ist eine Methode und Unit Testing ist ein Werkzeug, das von dieser Methode verwendet wird.

## Häufige Fragen

**Verschwendet TDD nicht Zeit?**

Auch wenn es auf den ersten Blick so aussieht, als ob es langsamer wird, spart es insgesamt Zeit, da es die Debugging-Zeit in der Zukunft reduziert.
