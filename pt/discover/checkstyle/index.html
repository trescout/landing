Auditoria de estilo e qualidade de código corporativo para Java

O Checkstyle é uma ferramenta líder de análise estática que audita código Java conforme os padrões Google Java Style e Sun em pipelines CI/CD.

Atualizações

  • 31 de agosto de 2026: 9.288 estrelas, versão v10.18.0 com suporte à sintaxe do Java 23 e regras AST aprimoradas.

O que você ganha

  • Alinhamento com padrões corporativos: Elimine debates de formatação em equipes com templates do Google Java Style e Sun.
  • Inspeção por árvore sintática abstrata (AST): Audite a estrutura gramatical semântica do código Java em vez de buscas de texto simples.
  • Extenso catálogo de regras embutidas: Monitore convenções de nomenclatura, espaçamento, aninhamento de blocos e complexidade ciclomática.
  • Ecossistema de compilação: Integração direta nos fluxos Maven e Gradle como barreira automatizada de qualidade.
  • Configurações XML flexíveis: Personalize níveis de severidade, regras específicas e filtros de supressão por arquivo.

Instalação

Baixar binário jar CLI independente
curl -sSL -O https://github.com/checkstyle/checkstyle/releases/download/checkstyle-10.18.0/checkstyle-10.18.0-all.jar

Execução

Executar auditoria com regras do Google Java Style
java -jar checkstyle-10.18.0-all.jar -c /google_checks.xml src/
# veya Maven ile:
./mvnw checkstyle:check

Arquitetura técnica e princípio de funcionamento

O Checkstyle converte código-fonte Java em árvores sintáticas abstratas (AST), navegando pelos nós com base em regras:

  • Parser Java e motor ANTLR: Decompõe classes, métodos e expressões em nós sintáticos por meio do motor ANTLR.
  • Padrão Visitor orientado a eventos: Cada regra observa estritamente os tokens AST de seu interesse, mantendo alta performance.
  • Filtros de supressão e comentários: Isole regras em trechos específicos com comentários CHECKSTYLE:OFF ou arquivos XML de supressão.

Conjuntos de regras e integração CI/CD

Incorporar o Checkstyle ao ciclo de desenvolvimento protege a integridade do código de forma contínua:

  • Barreira de Pull Request no GitHub Actions: Impeça a mesclagem de código fora do padrão nas branches principais executando o check em cada PR.
  • Plugins para IDEs (IntelliJ & Eclipse): Ofereça feedback em tempo real para os desenvolvedores durante a escrita do código.
  • Relatórios completos em HTML e XML: Gere métricas consolidadas e relatórios de violações para acompanhar a dívida técnica do projeto.

Perguntas frequentes

  • O Checkstyle corrige o código automaticamente? Não. O Checkstyle é um linter analítico que aponta infrações. A formatação automática é feita por utilitários como Spotless ou google-java-format.
  • Qual a diferença entre o padrão Google e o padrão Sun? As convenções Sun são históricas (indentação de 4 espaços, limite de 80 colunas). O Google Java Style reflete práticas modernas com 2 espaços e 100 colunas.
  • O Checkstyle pode interromper o build? Sim. Ao configurar failOnViolation no Maven ou Gradle, a compilação falha automaticamente quando ocorrem infrações.
  • Como é o desempenho em bases de código extensas? Por processar árvores sintáticas em memória, o Checkstyle analisa centenas de milhares de linhas de código em poucos segundos.
