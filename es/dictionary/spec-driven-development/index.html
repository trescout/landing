¿Qué es Spec-driven Development?

Antes de comenzar a codificar el software, todos los detalles y reglas se realizan de acuerdo con un documento predeterminado.

Definición

En este enfoque, lo que hará el software y cómo funcionará se define con una especificación detallada antes de escribir el código. El equipo aclara todas las reglas y los resultados esperados antes de ingresar al proceso de codificación. De esta forma se minimizan las incertidumbres que puedan surgir durante el desarrollo.

Analogía: Es similar a dibujar en detalle todos los planos arquitectónicos, los materiales a utilizar y las dimensiones de las habitaciones y obtener su aprobación antes de construir una casa.

Cómo funciona

Primero, los requisitos se recopilan y compilan en un documento. Los desarrolladores de software producen sus códigos utilizando este documento como guía. También se realizan pruebas según las normas de este documento.

Dónde se usa

Se prefiere en proyectos de software complejos, grandes sistemas corporativos y software crítico donde el margen de error debe ser bajo.

Suele confundirse con

Representa un proceso planificado y disciplinado en lugar de métodos flexibles donde se realizan cambios constantes durante el desarrollo.

Preguntas frecuentes

¿Te hace perder velocidad?

Aunque el proceso de planificación lleva tiempo al principio, a la larga ahorra tiempo ya que evita errores que pueden ocurrir más adelante.

¿Se pueden hacer cambios?

Se puede hacer, pero cada cambio requiere actualizar el documento.
