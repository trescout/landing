¿Qué es TDD?

Test-Driven Development

Es un método de desarrollo que se basa en preparar primero la prueba del código a escribir y luego escribir suficiente código para pasar esta prueba.

Definición

TDD se basa en la filosofía de "primero la prueba, luego el código". Primero escribes una prueba que define lo que debe hacer el código; Naturalmente, esta prueba falla porque aún no hay ningún código. Luego escribe el código más simple que pasará la prueba. Este ciclo garantiza que el software esté libre de errores en cada paso.

Analogía: Es como si un profesor que prepara un examen primero crea la clave de respuestas y luego espera que los estudiantes aprueben de acuerdo con esta clave.

Cómo funciona

Ciclo de tres etapas: 1. Prueba de escritura (Falla), 2. Escribir código (Pasar prueba), 3. Limpiar código (Refactorizar). Este proceso se repite constantemente.

Dónde se usa

Se aplica en equipos modernos de desarrollo de software, especialmente en proyectos donde la seguridad y la calidad están a la vanguardia.

Suele confundirse con

Se puede confundir con las pruebas unitarias; TDD es un método y Unit Testing es una herramienta utilizada por este método.

Preguntas frecuentes

¿TDD no hace perder el tiempo?

Aunque al principio pueda parecer que se ralentiza, en general ahorra tiempo ya que reduce el tiempo de depuración en el futuro.
