Pruebas unitarias y mocks en C++ con estándar de la industria

GoogleTest y GoogleMock proporcionan pruebas unitarias estándar de la industria, objetos simulados (mocks) y pruebas parametrizadas para C++ moderno.

Actualizaciones

  • 27 de agosto de 2026: 38.987 estrellas, versión v1.15.2 con soporte para conceptos de C++20 y validación de mocks mejorada.

Qué obtienes

  • Macros de aserción exhaustivas: Diagnósticos precisos mediante macros ASSERT_* (fatal, interrumpe el test) y EXPECT_* (no fatal, continúa).
  • Suite avanzada de mocks (GoogleMock): Aísle dependencias mediante MOCK_METHOD para simular interfaces y validar expectativas de llamadas.
  • Pruebas parametrizadas por valores: Ejecute la misma lógica de prueba en múltiples conjuntos de datos con plantillas parametrizadas.
  • Seguridad de subprocesos multiplataforma: Ejecución segura para subprocesos en Linux, macOS y Windows con pruebas de muerte (death tests).
  • Integración CI/CD e informes: Integración fluida con GitHub Actions y GitLab CI mediante formatos de salida XML y JSON tipo JUnit.

Instalación

Integración mediante CMake FetchContent
include(FetchContent)
FetchContent_Declare(
  googletest
  URL https://github.com/google/googletest/archive/refs/tags/v1.15.2.tar.gz
)
FetchContent_MakeAvailable(googletest)

Ejecución

Compilar y ejecutar pruebas con CTest
cmake -B build -S .
cmake --build build
ctest --test-dir build --output-on-failure

Arquitectura técnica y principio de funcionamiento

GoogleTest está estructurado sobre una arquitectura C++ modular optimizada para compiladores modernos:

  • Gestión del ciclo de vida y fixtures de prueba: Los métodos SetUp y TearDown garantizan asignación y limpieza predecibles de memoria en cada prueba.
  • Aislamiento de procesos para pruebas de muerte: Crea procesos secundarios aislados para verificar con seguridad caídas de procesos y estados de error.
  • Plantillas de pruebas parametrizadas por tipo: Valida clases genéricas con plantillas C++ en diversos tipos de datos sin redundancia.

Escenarios de prueba e integración con GoogleMock

Aislar dependencias mediante objetos simulados (mocks) en C++ moderno aporta ventajas prácticas inmediatas:

  • Abstracción de llamadas a bases de datos y red: Simule respuestas de API y latencias sin sockets reales mediante MOCK_METHOD.
  • Validación de conteo de llamadas y argumentos: Compruebe cuántas veces, con qué parámetros y en qué orden se invocaron métodos mediante EXPECT_CALL.
  • Pruebas de resiliencia ante excepciones: Valide la gestión robusta de fallos en rutas que lanzan excepciones usando EXPECT_THROW.

Preguntas frecuentes

  • ¿Cuál es la forma moderna de incluir GoogleTest en un proyecto? En proyectos con CMake moderno, el módulo FetchContent es el enfoque estándar recomendado, integrando y compilando el código fuente sin dependencias externas.
  • ¿Cuál es la diferencia entre EXPECT_* y ASSERT_*? Las macros EXPECT_* registran fallos y permiten que el test continúe ejecutándose. Las macros ASSERT_* abortan de inmediato la función de prueba actual.
  • ¿GoogleMock es una biblioteca independiente? GoogleMock era un proyecto separado inicialmente, pero está unificado dentro del repositorio de GoogleTest desde hace años.
  • ¿GoogleTest es seguro para subprocesos? Sí. En sistemas con pthreads y en Windows, GoogleTest es thread-safe y sincroniza correctamente aserções ejecutadas desde subprocesos concurrentes.
