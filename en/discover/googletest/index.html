Industry-standard C++ unit testing and mocking

GoogleTest and GoogleMock provide industry-standard unit testing, mock objects, and parameterized test suites for modern C++ software.

  • ★ 38,987
  • C++
  • GitHub Trending · 2026-08-27

Updates

  • August 27, 2026: 38,987 stars, v1.15.2 release featuring C++20 concepts and enhanced mock verification.

What you get

  • Comprehensive assertion macros: Clear diagnostics using ASSERT_* (fatal, aborts test) and EXPECT_* (non-fatal, continues test) macros.
  • Advanced mocking suite (GoogleMock): Isolate dependencies using MOCK_METHOD to easily mock interfaces and specify invocation expectations.
  • Value-parameterized tests: Execute identical test logic across dozens of input datasets using parameterized test patterns.
  • Cross-platform thread safety: Thread-safe execution on Linux, macOS, and Windows with robust death tests for crash verification.
  • CI/CD and reporting integration: Seamless pipeline integration with GitHub Actions and GitLab CI via JUnit-compatible XML and JSON outputs.

Installation

Integrate via CMake FetchContent
include(FetchContent)
FetchContent_Declare(
  googletest
  URL https://github.com/google/googletest/archive/refs/tags/v1.15.2.tar.gz
)
FetchContent_MakeAvailable(googletest)

Running it

Build and run tests via CTest
cmake -B build -S .
cmake --build build
ctest --test-dir build --output-on-failure

Technical architecture and working principle

GoogleTest is architected around a modular C++ design optimized directly for modern compilers:

  • Test fixture and lifecycle management: SetUp and TearDown methods guarantee deterministic resource allocation and cleanup for every test.
  • Process isolation for death tests: Forks isolated child processes to safely verify assertions, crashes, and error exit statuses.
  • Type-parameterized test templates: Provides type-parameterized test infrastructure to validate templated classes across diverse types.

Testing scenarios and GoogleMock integration

Isolating dependencies using mock objects in modern C++ delivers substantial practical advantages:

  • Abstracting network and database calls: Simulate remote API responses and latencies without opening real network sockets using MOCK_METHOD.
  • Invocation count and argument verification: Inspect how many times, with which parameters, and in what order methods were invoked via EXPECT_CALL.
  • Resilience testing under exceptions: Verify robust error handling across throwing code paths with EXPECT_THROW assertion macros.

Frequently asked questions

  • What is the modern way to include GoogleTest in a project? In modern CMake projects, CMake's FetchContent module is the recommended approach, automatically downloading and compiling GoogleTest as part of the build without external package managers.
  • What is the difference between EXPECT_* and ASSERT_*? EXPECT_* macros log failure details while allowing execution of subsequent statements in the test. ASSERT_* halts execution of the current test function immediately upon failure.
  • Is GoogleMock a separate library? GoogleMock was originally a standalone project but has long been merged into the GoogleTest monorepo; both libraries are installed and configured together.
  • Is GoogleTest thread-safe? Yes. On systems supporting pthreads and on Windows, GoogleTest is thread-safe, safely synchronizing test assertions from concurrent worker threads.
